Backend of the Belvedere Glacier monitoring project (Macugnaga, VCO): GNSS surveys of a network of points on and around the glacier, survey products, and time-lapse camera images. One PostgreSQL/PostGIS database is used by this admin, by QGIS (direct connection) and by the public web viewers (through the /surveys/ and /cams/ API).

2. Coordinates and heights

Project CRS: EPSG:7791RDN2008 / UTM zone 32N (ETRF2000, epoch 2008.0) — the Italian GNSS network's realization. East/North of every measurement are in this system.
Heightsh is the ellipsoidal height (GRS80); h_orto the orthometric height, always referred to ITALGEO05.
Latitude / longitudeShown as WGS 84 (EPSG:4326). The values are numerically identical to RDN2008 geographic (null transformation), but today's WGS 84 / ITRF differs from ETRF2000 by about 0.45 m.
GeocentricX, Y, Z in RDN2008 (EPSG:6704), on the monographs and in the CSV export.
Local ENU (SRID 990001)A glacier-local frame with origin on D12: true distances, no map distortion. Its U is not an altitude (height above the tangent plane at D12 + 1000 m).

3. What the database computes

When a measurement is saved, database triggers derive from East/North/h: the point geometry, latitude and longitude, h_orto (from the ITALGEO05 geoid) and the ENU position. Edit only East, North and h; the rest follows. Measurement times are stored in UTC and shown in local time (Europe/Rome) where marked “local”.

4. Points

  • The list opens on active points only. Inactive points are the history of the glacier's movement: choose Status → All points or Inactive (history) to see them.
  • Other filters: fixed/moving, measured in a year, last measured in, number of measurements, with/without photos. The map above the list shows each point at its latest position and follows the filters.
  • The edit form holds the point's texts (target, description, notes) and, under Latest data, its latest coordinates and photos.
  • A point with measurements cannot be deleted by mistake. The action Delete selected points AND all their measurements does it explicitly.
  • Hover over a column header or a field name for its description.

5. Measurements and photos

  • Filters: survey year, survey, fixed/active point, survey mode, with photos. The map shows the filtered measurements.
  • Survey mode (e.g. RTK RADIO, STATICO) belongs to each measurement.
  • Photos: in a measurement's form, add a photo in the empty row, replace one by choosing a new file, remove one with Delete. Photos are private; the links in the admin work for staff only.

6. Importing a survey campaign

  1. Create the survey (Surveys → Add): date and year.
  2. Import the measurements from CSV: Measurements → Import. Columns: point_label, survey_id or survey_date (DD/MM/YYYY, of an existing survey), east, north, h, optional std_east, std_north, std_h, meas_date, meas_strategy, notes. Labels match case-insensitively; an unknown label creates a new point (check it afterwards). The import shows a preview before confirming.
  3. Field photos of the campaign (named Img_<LABEL>_<DDMMYY>_<HHMMSS>.jpg) are attached with the command import_point_photos (see 11), which also sets each measurement's time.
  4. Update the active flag of points that are lost or replaced.

7. Point movements

Point movements lists every moving point between two consecutive measurements: horizontal displacement d and velocity v (the main values, m and m/yr), the vertical part (d_h, v_h), 3D values that include glacier surface lowering, and the acceleration a (m/yr², between consecutive yearly intervals). Year (end) is the year of the later measurement. Is annual marks pairs about one year apart. The map draws all yearly movements, coloured by velocity class. Fixed points are not included.

8. Monographs and exports

  • One point: View monograph / Export monograph PDF at the top of its form, or View · PDF in the Points list.
  • Many points: View monographs / Export monographs PDF on the Points list cover the points currently listed (filters apply), in one document with an index.
  • CSV: Export CSV on the Points list: the listed points with everything about their latest measurement.
  • A monograph uses the point's latest measurement and its two most recent photos; empty boxes mean no photo yet.

9. Cameras and images

Cameras (location, calibration, S3 folder) are managed under Image index. Their images are catalogued from the S3 bucket by the command index_s3_images; previews and thumbnails are generated on demand.

10. Rules

  • The database is shared with QGIS: never change tables or views from QGIS or pgAdmin. Structure changes go through the code (migrations).
  • Do not edit the derived fields (latitude/longitude, h_orto, ENU, geometries).
  • In QGIS, never reproject an ENU layer; keep the project CRS at 990001 for ENU data.
  • The local reference frame (on D12) is frozen: it is never changed.
  • Take a backup before large changes (scripts/localdb.sh pull-live).

11. Command-line tools (maintainers)

Run from the project folder with uv run python manage.py <command>. Commands that write are dry runs unless given --apply.

import_point_photos DIR --year YYYYAttach a campaign's field photos (upright) and set measurement times.
import_monograph_texts FILE.pub …Fill point texts from the Publisher monographs (needs LibreOffice).
generate_monographs [--until-year Y] [--split]Monograph PDFs from the command line, also as of an earlier year.
merge_duplicate_pointsMerge points whose labels differ only by case.
index_s3_imagesCatalogue camera images from S3.
validate_reference_frameCheck the local ENU frame (read-only).

scripts/localdb.sh runs a local copy of the database: pull-live copies production into it (production is only read), run starts the admin on it, test runs the tests.
